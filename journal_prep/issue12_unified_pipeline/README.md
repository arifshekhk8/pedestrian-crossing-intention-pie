# Issue 12 — The unified, model-agnostic training pipeline (+ replication annexes)

**Why this exists (audit finding UNIFIED-DESIGN / ENGINE-DEVICE-CONFOUND, 2026-07-13):**
until now every cross-family claim spanned engine boundaries — the canonical BiLSTM was
trained by `pipeline/04_train_bilstm.py` on local CPU, the transformer by
`transformer/phase1_setup/02_train_transformer.py` on Kaggle T4, and the F1-first
program by two line-faithful forks on MPS. This folder ends that: **one engine, one
frozen protocol, every model family** — the journal-grade pipeline for the BiLSTM and
Transformer today, and for the planned GRU / bidirectional-RNN follow-up.

## Files

- **`12_unified_engine.py`** — THE pipeline. One `train_run(family, cfg, seed, device,
  data, pos_weight, select, out_dir)` for `bilstm | transformer | gru | birnn`
  (`MODEL_REGISTRY`). Frozen (never per-family): data + split asserts, train-only
  z-score, loss/pos_weight anchor, batch 32, ≤100 epochs, patience-15 early stop +
  plateau on val AUC, checkpoint rule (`select="f1"` hybrid or `select="auc"` frozen
  legacy), full-metric eval @0.5, one hardened `set_seed` (CUDA-safe cuDNN flags),
  provenance-complete `final.json` (family, cfg, seed, pos_weight, device,
  torch_version, select, both checkpoints' val metrics). Parameterized: the model
  builder and the cfg-driven recipe (lr, weight_decay, adam/adamw-with-no-decay-groups,
  plateau/warmup_cosine) — identical options for every family. **No test code path.**
- **`12_equivalence_check.py` → `12_equivalence_report.md`** — proof this IS the
  published pipeline: (G-A) bit-identical to the f1_optimization engine on CPU;
  (G-B) reproduces the published transformer cell **exactly** on MPS; (G-C) GRU/biRNN
  functional smoke. **ALL GATES PASS.** Also documents the measured MPS caveat:
  nn.LSTM training on Apple MPS is bit-deterministic only within an identical process
  history (fresh 0.8239 / warmed 0.8344 / mid-driver 0.8387 val F1 for the same cell),
  the transformer shows no such dependence, and **CPU is fully context-free**
  (0.8272 in every tested context) → recurrent-family training that must be exactly
  reproducible runs on CPU (~15 s/run here).
- **`12_replication_cpu.py` → `12_replication_report.md`** — single-engine,
  single-device (CPU) replication of the three F1-first endpoints, all arms retrained
  fresh (selections frozen from `f1_optimization/04_selection.json`), plus the G1
  test-side counterfactual arms (A3f/B3f: same configs with AUC checkpointing).
  Directly answers "is the F1-first conclusion an artifact of mixed engines/devices?"
- `runs_replication/<cell>/seed<k>/` — the replication run dirs (full artifact set).

## How future GRU/RNN work plugs in

`MODEL_REGISTRY["gru" | "birnn"]` already builds the recurrent twins of the BiLSTM
(same input projection, bidirectional recurrence, last-step readout — only the cell
type differs, so the comparison isolates the cell exactly as the transformer study
isolated attention). Run e.g.:

```bash
python journal_prep/issue12_unified_pipeline/12_unified_engine.py \
    --family gru --seed 42 --device cpu --select f1 --out_dir <run_dir>
```

then 5-seed it, tune τ\* on val, and evaluate test once through a designated final
script — the same discipline as every published result in this repo.
