# draw.io versions of the manuscript figures

Eight `.drawio` files, one per figure, that open and edit in the desktop draw.io
app. Nothing is a pasted image: every box, bar, curve, tick and label is a real
shape you can select, move and restyle.

```
fig1_pedestrian_statistics.drawio    fig5_curves.drawio
fig2_system.drawio                   fig6_forest.drawio
fig3_protocol.drawio                 fig7_ablations.drawio
fig4_leakage.drawio                  fig8_latency.drawio
```

`preview/` holds a PNG of each, exported with the draw.io CLI, so you can see
what a file contains without opening it.

## Opening them

Double-click any `.drawio` file, or from the terminal:

```bash
open -a draw.io fig2_system.drawio
```

## Regenerating

```bash
source .venv/bin/activate
python paper_and_artifacts/Journal_writing/drawio/make_drawio_figures.py
```

Re-export the previews after editing the generator:

```bash
cd paper_and_artifacts/Journal_writing/drawio
for f in *.drawio; do
  /Applications/draw.io.app/Contents/MacOS/draw.io --no-sandbox -x -f png -s 2 \
    -o "preview/${f%.drawio}.png" "$f"
done
```

The CLI also exports PDF and SVG (`-f pdf`, `-f svg`), which is what you would
use if these ever replaced the matplotlib figures in the manuscript.

## The one rule to know before editing

These canvases are 1200–1500 pt wide and MDPI's `\textwidth` is **394 pt**, so a
figure is shrunk to about a third when it goes on the page. Left alone, an 11 pt
label would print at 3.2 pt.

`drawio_lib.Doc` therefore pre-multiplies every font size and stroke width by

```
fk = (TARGET_PT / 11) * (canvas_width / 394.36)
```

with `TARGET_PT = 5.2`, which puts body labels at 5.9–7.7 pt on the printed page
against the matplotlib figures' 6.0 pt. `TARGET_PT` is not a free knob: raising
it to 8 inflates the labels past the boxes that hold them, because the ratio of
text size to box size in this layout is what it is.

**The consequence for editing:** any vertical offset you write must be a multiple
of `d.fk`, not a fixed number of points. Fixed offsets were what put Figure 3's
TTE arrow on top of its own subtitle once the subtitle grew from one line to two.
Figure 3 is the worked example; its layout is a table of `B_*` band constants,
all in units of `k`.

## What is drawn from what

Figures 2 and 3 are schematics. They are laid out by hand in
`make_drawio_figures.py`, and draw.io is a better tool for them than matplotlib
ever was: they are pictures of a system and a protocol, with no data in them.

The other six are data plots. Their bar lengths, curve points and interval
positions are **computed from the same source files** the matplotlib figures
read, not measured off the published images:

| Figure | Source |
|---|---|
| 1 | WHO 2023 and NHTSA DOT HS 813 727 counts, as recorded in `STATISTICS_SOURCES.md` |
| 4 | `journal_prep/issue1_leakage_audit/leakage_per_sequence.csv` and the issue-2 equivalent; the rank-biserial effects are recomputed here with the same Mann-Whitney test |
| 5 | `../MDPI_Article_Template/figures/_probs.npz`; ROC and PR curves are computed with scikit-learn and thinned to 44 points so the polyline stays editable |
| 6 | the stored cluster-bootstrap outputs, transcribed identically to `make_fig6_forest.py` |
| 7 | `journal_prep/issue6_window_tte_ablation/06b_matched_tte_results.csv`, averaged over seeds, plus the multi-seed ablation summaries |
| 8 | `journal_prep/Analysis/latency_comparison.csv` and the issue-9 latency report |

This matters more than it sounds. Redrawing a chart by hand means nudging bars
until they look about right, and a figure that has drifted from its own results
is worse than no figure. Because these are generated, the draw.io bar and the
paper's bar are the same length by construction. Edit the styling freely; if you
move a bar, you have changed a number.

## Figure 9 is not here

It is two photographs from the PIE test set with detector boxes drawn on them.
There is nothing in it to redraw as vector shapes. It stays as
`../MDPI_Article_Template/figures/fig9_qualitative.pdf`, generated by
`make_fig9_qualitative.py`.

## These do not replace the manuscript figures

`main.tex` still points at the matplotlib PDFs in
`../MDPI_Article_Template/figures/`. Nothing here changes the paper. That is
deliberate: the matplotlib figures are vector PDFs at exact journal column
widths with typographic control MDPI expects, and swapping them for draw.io
exports would be a step down for submission. Use these for editing, for slides,
and for anywhere a figure needs to be reshaped quickly.

If you do want one in the paper, export it to PDF and point the `\includegraphics`
at the result:

```bash
/Applications/draw.io.app/Contents/MacOS/draw.io --no-sandbox -x -f pdf --crop \
  -o ../MDPI_Article_Template/figures/fig2_system.pdf fig2_system.drawio
```

`--crop` trims the page to the drawing, which you want; without it you get the
whole canvas with white margins.
